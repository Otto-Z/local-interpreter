# 本地同传 · Android 平板版

把 macOS 版「本地同传」的全部功能搬到 Android 平板上：麦克风 / 系统声音 / 音频文件 → 本地 VAD 分句 → 本地语音识别 → 本地大模型流式翻译 → 实时字幕；并能归档课程、检索讲义、做课堂助教。**全部在本机完成，不联网、不上传。**

## 功能

**实时同传**
- 麦克风、系统音频（Android 10+，需录屏授权）、音频文件三种来源；音频文件可以由其它应用「打开方式」直接送到本地同传。
- 音频文件支持 WAV（16 位 PCM）以及系统解码器支持的 MP3 / M4A / AAC / OGG / FLAC；不支持的格式会在界面上明确报错，不会静默结束。
- Silero VAD 自动分句；SenseVoice 离线识别（中/英/日/韩/粤，自带标点）。
- 本地 Hy-MT2-1.8B（GGUF，llama.cpp）流式翻译；也可切到任意 OpenAI 兼容接口。
- 边说边译草稿、正式译文替换、原文/译文双语字幕、低置信度提示。
- 全屏字幕模式；浮字幕（悬浮在所有应用上方，可拖动、可调字号和背景不透明度）。
- 暂停/继续、标记当前句、导出 SRT、本次首字延迟显示。
- 说话人区分（CAM++ 声纹本地聚类，字幕标注「说话人 1/2…」，可重命名）。
- 上下文同音字校正（可选，用翻译模型修正识别文本）。

**课堂助教**
- 助教模型可选 **Qwen3-4B**（质量优先，约 2.5GB）或 **Qwen2.5-1.5B**（省内存，约 1.1GB），在设置 → 课堂助教里切换。
- 右侧栏每 60 秒生成「本场要点」，也可手动「最近总结」。
- 自动识别课堂提问并作答，答案标注来源（课堂内容 / 课件 / 模型知识 / 综合），中文答案附目标语言对照。
- 手动提问；下课自动生成标题、摘要，并按设置提取本课新术语。

**课程与课次**
- 课程 → 课次的归档；未分类课次有单独入口；课程新建、重命名、删除、笔记、导出。
- 课次详情：双语字幕、说话人、逐句录音回放、标记回听、问答、复习题、导出 SRT / Markdown / JSON。
- 搜索课次标题、摘要和全部课堂原话。
- 课程资料：上传 PDF / DOCX / PPTX / TXT / Markdown，本地解析、分块、按关键词检索；问答/预习会引用课件并标注页码。
- 术语表：手动添加或 AI 自动提取；用于该课程的翻译提示。
- 课前预习提纲；课后复习题（可复制到 Anki 等工具）。

**设置**
- 内置模型 / OpenAI 兼容 API 两种翻译方式；助教可单独用 API。
- 助教模型可在 4B 与 1.5B 之间切换。
- 模型管理：SenseVoice、Hy-MT2 Q4、Hy-MT2 2bit、Qwen3-4B、Qwen2.5-1.5B；断点续传、国内镜像、删除。
- 识别语言、停顿判定、线程数、字幕字号/行数/原文显示、主题、存储清理。
- 模型自检（用一段内置中文测试音频跑「识别 + 翻译」，不经过麦克风）、翻译评测。

## 系统要求

- Android 10（API 29）及以上；仅 `arm64-v8a`。
- 建议 8GB RAM：翻译模型约 1.2GB，助教模型约 2.5GB，识别模型约 240MB。
- 首次使用需下载模型（约 1.4GB；助教模型另约 2.5GB，可选），约需 5GB 可用空间。
- 系统音频采集只能录到允许被录制的应用（DRM/受保护内容除外）；部分厂商系统会限制后台录音，遇到问题请把应用加入电池优化白名单。

## 构建

需要 JDK 17、Android SDK（platform 34、build-tools 34）、NDK 27.2、CMake 3.31.5。

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
cd android
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

签名版：

```bash
cd android
./gradlew :app:assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

（`app/localinterpreter.jks` 是仓库自带的本机测试签名，正式分发请换成自己的 keystore。）

## 架构

```
麦克风 / 系统音频 / WAV 文件
   │ 16kHz 单声道 PCM
   ▼
Silero VAD（sherpa-onnx，512 点窗口）
   ▼
SenseVoice-Small（sherpa-onnx · ONNX Runtime）
   ▼
llama.cpp（JNI）── Hy-MT2-1.8B GGUF 流式翻译
   │
   ├─ CAM++ 声纹（sherpa-onnx）→ 说话人聚类
   ├─ 课堂助教：Qwen3-4B GGUF（可选）→ 要点 / 问答 / 标题 / 术语 / 复习题
   └─ Room 之外的轻量 SQLite：课程、课次、字幕、资料分块、术语、书签、问答
```

- 界面：Jetpack Compose，平板横屏为「字幕 + 助教」双栏，课程页为「列表 + 详情」双栏；竖屏自动切为单栏。
- 原生层：`app/src/main/cpp/llama-jni.cpp` 提供每个模型独立的上下文、流式回调和取消；`jniLibs/arm64-v8a` 为 sherpa-onnx/onnxruntime 预编译库。
- 模型：SenseVoice 与两套 GGUF 在设置里下载；Silero VAD 和 CAM++ 随 APK 附带。下载支持断点续传并校验文件完整性，但建议保持应用在前台；大模型下载期间不要清后台。
- 原生库（llama.cpp、sherpa-onnx、ONNX Runtime）已按 16KB 内存页对齐，兼容 Android 15 及之后的设备。
- 数据库与音频保存在应用私有目录（`/data/data/com.localinterpreter.tablet/`），不向外部发送。

## 排查：识别正常但字幕消失 / 翻译不动（2.2.2）

2.2.2 针对这类问题做了几处兜底：

1. **原文不会再被翻译失败吞掉**：每句识别完成后先入库并显示；翻译失败时字幕会显示失败原因，顶部状态也会显示。原文、录音和课次都会保留。
2. **模型完整性检查**：翻译/助教模型文件不完整、不是 GGUF、或下载中断时，内置翻译会拒绝启动，设置 → 模型管理会显示「文件不完整：xxMB / 约 yyMB」。点「重新下载」会断点续传；实在不行点「删除」再下载。
3. **崩溃/被后台杀掉后恢复**：下次打开应用会恢复最近 24 小时内未正常结束的课次字幕；右下角出现「补译」按钮，修好模型后点一下即可补齐译文。
4. **诊断日志**：设置 → 关于 → 查看日志 / 复制日志。日志会记录设备型号、内存、模型加载耗时与失败原因、每句识别/翻译结果。遇到问题请把日志发来。
5. **课次归属**：课次详情右上角「归入课程」可以把未分类课次移到任意课程；课程删除后课次会回到未分类，课程资料和术语会一并删除。
6. **API 地址**：Android 上的 `127.0.0.1` 指平板自己；如果模型服务跑在电脑上，请填电脑的局域网 IP（例如 `http://192.168.1.100:8000/v1`），并确认同一 Wi-Fi。
7. **内存不足**：设置 → 翻译方式里换成 2bit 翻译模型（约 600MB，更快更省内存）；助教可换 1.5B 轻量模型（约 1.1GB），4B 模型约 2.5GB 建议 8GB 内存；内存小的设备也可把助教改成 API。

如果你在旧版本上下载过模型，升级后请先检查「模型管理」里有没有「文件不完整」的提示，并重新下载。不要边下载模型边开始同传。

其他 2.2.2 加固：识别/翻译模型加载前检查可用内存（不足时明确提示而不是强杀进程）；麦克风、系统音频、文件读取失败会显示错误并结束会话；空课次自动清理；数据库启动损坏时自动备份重建；所有字幕、问答、术语写入失败都有日志与界面提示。

## 2.2.3：全量代码复查

2.2.3 逐文件复查了启动、音频、识别、翻译、字幕、助教、课程、导入导出和设置页面，修掉以下会影响可用性的问题：

1. **旧数据库升级不再崩溃**：建表与补列改为幂等（`CREATE TABLE IF NOT EXISTS` + 逐列检查）。从旧版本升级、或数据库缺少 `quizzes` 等表时，打开应用会自动补齐，而不是在查询时报「no such table」。
2. **收尾阶段不再产生孤儿字幕**：结束同传时如果仍有识别/翻译在途，会保留课次并等结果落库，不会先删空课次再写入。
3. **浮字幕**：译文缺失时回退显示原文（不再只显示「正在听…」）；拖动限制在屏幕范围内，不会被拖出屏幕找不回来。
4. **助教超时放宽**：本地 1.5B/4B 生成上限从 120 秒放宽到 240 秒，慢速平板生成较长答案不会误报超时；API 仍为 120 秒。
5. **导出结果如实反馈**：SRT / Markdown / JSON / 课程导出写入失败会提示「导出失败」，不再误报成功。
6. **导入更稳**：资料扩展名可从 URI 推断；TXT 自动识别 UTF-8 / GB18030；资料入库失败会整体回滚，不留下孤儿分片。
7. **运行中锁定模型选项**：同传进行时禁用翻译/助教模型切换，避免中途换模型造成个别句子翻译失败。
8. **API 兼容性**：兼容不声明 `text/event-stream` 却返回 SSE 行、或只在 `message.content` 里给结果的服务。
9. **自检释放资源**：识别自检异常时也会释放识别器和 VAD，不会额外占用几百 MB 内存。
10. **其它**：数据库保存复习题改为事务；创建课程/资料插入失败会明确报错；未入库的字幕不再允许添加失效标记。


## 2.2.4：识别文字保留修复

针对“识别文字过一会就消失”的根因修复：

1. **VAD 不触发也会落库**：远场/嘈杂环境下 Silero VAD 可能长时间不判定分句，之前文字只存在于“预览行”，每次预览刷新就把上一段顶掉，数据库里没有字幕。现在连续 6 秒没有 VAD 分句且仍有识别文本时，会把当前缓冲强制送入最终识别并入库；暂停和结束时也会提交剩余内容。
2. **静音不再产生幻觉字幕**：能量低于阈值的静音/底噪不再显示预览，也不会被兜底提交，避免出现“Yeah.”“是的。”这类固定幻觉。
3. **主记录页始终显示识别原文**，「字幕模式显示原文」开关现在只影响全屏字幕和浮字幕；原文无论如何都会保留在实时记录和课次详情里。
4. **暂停/结束不丢最后一段**：暂停或结束同传时，未触发 VAD 的最后一段音频也会识别并保存。
5. **诊断日志**：日志新增“识别兜底 / 当前显示 N 句 / 丢弃过期字幕”，方便确认文字是否已经入库。

## 2.2.5：第二轮全量复查

这一版把直播、模型、数据库、课程页和 Android 生命周期分四块重新审阅，并跑了 Android Lint。修复的主要问题：

1. **原生层崩溃**：切换识别语言时，旧 recognizer 可能在解码过程中被释放（use-after-free）。现在加载、替换、释放和识别共用同一把锁；模型 `close()` 也会等待正在进行的 JNI 生成退出，避免模型切换/删除时崩溃。
2. **后台任务串会话**：停止后残留的识别预览、总结、说话人、翻译补译不会再写入新会话；停止/开始时会取消旧的助教生成，总结只写回发起它的课次。
3. **停止与启动状态机**：启动令牌防止已取消的启动覆盖新会话；停止期间按钮显示「收尾中…」并禁用，前台服务在清空/关闭错误提示后也一定会退出。
4. **时间轴**：麦克风/系统音频暂停后再继续，字幕时间会补上暂停时长，不再整体提前。
5. **识别/翻译超时**：用看门狗真正中断阻塞中的 JNI/HTTP 调用；超时前已生成的内容会保留，而不是整段丢弃。
6. **API 兼容**：`content:null` 不再变成字符串 "null"；所有 API 调用共用连接池；兼容不声明 SSE 的服务；下载续传校验 `Content-Range`，模型文件最小尺寸上调，避免半截文件被当成就绪。
7. **数据库安全**：只有确认损坏才重建，且备份按时间戳保留、不再覆盖旧备份；进行中的课次禁止删除；结束会话不再覆盖用户手动改过的标题（新增 `title_source`）。
8. **资料导入**：UTF-8/UTF-16/GB18030 正确识别；ZIP 解压和 PDF 大小设上限，OOM 时清理临时文件；导入期间课程被删除会拒绝写入；课程切换时资料/课次列表按课程隔离，避免误删。
9. **界面**：浮字幕实时响应字号/透明度/行数设置并显示启动失败原因；主记录页向上翻看时不再被流式 token 拽回底部；窄窗口下助教面板和底部控制区自适应；导出写入移到 IO 线程并如实提示失败。
10. **其它**：线程数修改后下次加载生效；日志读取改为只读末尾 256KB；通知权限被拒时会提示；通过文件管理器再次打开音频不会在重建时重复打开。



## 2.2.6：API 兼容与识别提速

1. **API 空译文定位与修复**
   - 兼容 `content` 为字符串、数组（多段文本）、非流式 JSON、NDJSON 等多种返回格式。
   - Qwen3 等思考模型会自动附带 `chat_template_kwargs: {enable_thinking:false}`，服务端不接受（HTTP 400）时自动去掉参数重试。
   - 如果接口只返回 `reasoning_content`（思考过程），会明确提示“只返回了思考内容”，而不是误报“内存不足”。
   - 接口地址填 `http://IP:端口` 或 `http://IP:端口/v1` 都可以；前者返回 404 时会自动尝试 `/v1/chat/completions`。
   - 空响应、HTTP 错误会把响应开头写入诊断日志，设置里的「测试翻译」也会显示具体原因。
   - 内置模型和 API 的空输出提示已分开，不再把 API 问题说成内存不足。
2. **音频文件全速转写**：文件源不再按 1× 实时速度喂入，而是按设备处理能力全速跑；用待识别队列做反压，长音频不会堆爆内存，暂停/继续仍然有效，全部识别/翻译完成后再结束课次。81 秒测试音频在模拟器上约 6 秒处理完。
3. **实时识别提速**
   - 边说边译的预览解码窗口从 10 秒降到 6 秒，间隔从 700ms 放宽到 900ms，把 CPU 留给最终识别。
   - 草稿翻译间隔从 1.2 秒放宽到 2.5 秒，最多 80 token。
   - 推理线程默认值改为 CPU 核心数/3（识别线程仍为核心数/2），避免识别和翻译互相抢核。
4. 文件转写时不再运行实时预览 ASR，全部算力用于最终识别。
5. **实时字幕先出后改**：VAD 切句时，已有预览文字会立即变成正式字幕行（译文稍后补上），最终 ASR 完成后再原地替换；慢设备上不必再等最终识别结束才看到原文。

## 2.2.7：进一步提速

1. **音频文件不再限速**：取消了 4× 上限，改为按设备处理能力全速喂入；待识别队列超过 6 段时自动反压，处理完所有识别/翻译后才结束课次。模拟器上 81 秒音频约 6 秒完成 5 句识别和翻译。
2. **实时识别更快出字**：连续讲话的强制切句上限从 14 秒降到 8 秒；预览窗口为 6 秒，设备识别偏慢时自动降到 4 秒并放宽频率。
3. **自适应让出 CPU**：如果最近一句最终识别超过 1.8 秒，本场自动暂停「边说边译」草稿；识别慢时预览也会避开翻译/草稿任务，把 CPU 留给最终识别。
4. 底栏新增「识别 xxx ms」，可直接看到每句最终识别耗时，方便判断是识别慢还是翻译慢。



## 2.2.8：修复“没有识别到音频”

1. **全速文件转写不再丢帧**：2.2.7 的文件线程在 VAD 来不及消费时只重试 1 秒就丢帧，慢设备上可能整段音频丢失。现在改为真正的阻塞反压（文件线程等待 VAD 消费，绝不丢帧），文件模式音频缓冲从 64 帧提高到 256 帧。405 秒测试音频在模拟器上约 12 秒完成 25 句识别。
2. **音频没进来会直接提示**：麦克风/系统音频连续 5 秒没有收到任何音频帧时，主界面显示“没有收到音频数据：请检查录音权限…”，不再安静地什么都不显示。
3. **连续识别为空会提示**：连续 3 个 VAD 分句最终识别为空时提示检查音源音量、识别模型和线程设置。
4. **低音量更宽容**：VAD 阈值从 0.4 降到 0.35；预览/兜底提交的能量阈值从 0.003 降到 0.0015，音量偏低的麦克风不再被当成静音完全过滤。

## 2.2.9：修复“识别一句后不再出声”

1. **不再在会话中途 flush VAD**：暂停和“识别兜底”原来会调用 `segmenter.flush()`。部分 sherpa 版本在 flush 后不再继续分句，表现就是识别出一句后永远停在“正在聆听”。现在只在会话结束时 flush。
2. **实时切句恢复 14 秒上限**：2.2.7 把实时强制切句改成 8 秒，属于未在真机验证的参数变更，已恢复为 14 秒。
3. **输入电平可见**：麦克风/系统音频运行时，如果还没有字幕，界面会显示“正在听麦克风… 输入电平 x%”，低于 0.5% 时提示检查麦克风/音量或确认系统声音正在播放。
4. **音频处理异常会显示**：音频处理协程如果异常退出，主界面直接显示“音频处理异常：…”，不再静默停住。
5. 保留 2.2.8 的文件阻塞反压（不丢帧）、5 秒无音频帧提示、连续 3 句识别为空提示。

## 2.2.10：真机日志修正

根据 Xiaomi Pad（8 核 / 11GB）日志：ASR 预览和翻译在跑，但完全没有 `VAD 分句`，同时本地翻译用了 **2 线程、每句 7–8 秒**。

1. **10 秒强制兜底切句**：即使 VAD 一直认为“正在说话”、迟迟不产出一句，只要已有预览文字，满 10 秒就强制把当前缓冲送入最终识别并入库。这是“完全不分句”时的最后保障。
2. **8 核以上设备推理线程恢复 4**：2.2.6 曾把默认推理线程降到 2，导致本地翻译每句 7–8 秒；8 核以上设备自动恢复为 4（识别线程仍为 4）。手动调过其他线程数的保留。
3. **新增预览识别日志**：日志里会出现 `预览识别 xxxms text=x字 lang=xx`，可以确认预览 ASR 是否在正常工作。
4. **可导出的诊断报告**：设置 → 关于 → 「导出日志」会生成一份 txt，包含设备型号/系统/内存、当前模型与线程设置、直播状态，以及当前日志和上一份滚动日志；不包含录音内容和 API Key。「复制日志」也带同样的配置头。音频采集、翻译请求、前台服务等关键步骤都补了日志。

## 2.2.11：修复麦克风数字静音

诊断报告显示小米平板麦克风输入的 RMS 只有 0.0001–0.0002，属于数字静音（不是低音量），因此识别、VAD 都没有内容可处理。

1. **麦克风改用通用 `MIC` 音源**：不再使用 `VOICE_RECOGNITION`，避免部分 HyperOS/Android 16 机型上该音源返回全零。
2. **48kHz / 44.1kHz 采集后重采样到 16kHz**：不再假设设备原生支持 16kHz 麦克风采集；按 48k、44.1k、16k 顺序自动选择可用采样率。
3. **连续 5 秒输入电平≈0 时直接弹错误**：提示检查系统麦克风/音量开关、其它应用占用，或改用音频文件；不再只显示“正在聆听”。
4. 如果你把「识别语言」设成了 English 却说中文，识别质量也会明显变差；中文课堂请用「自动」或「中文」。

## 2.2.12：麦克风被系统拦截时直接报错

1. **启动前检查 AppOps**：HyperOS 的隐私开关可能把 `RECORD_AUDIO` 的 AppOps 设为 ignored（权限界面仍显示已授权）。现在会直接报“系统隐私设置禁止了麦克风”，而不是给全零音频。
2. **检查系统麦克风静音开关**：`AudioManager.isMicrophoneMute` 为 true 时直接提示去控制中心打开。
3. **检查录音状态与路由**：`startRecording()` 后若未进入 RECORDING 状态会报错；日志记录实际输入设备名称/类型，便于判断是否路由到了无信号的蓝牙/键盘麦克风。
4. 保留 2.2.11 的 `MIC` 音源 + 48kHz/44.1kHz 采集重采样到 16kHz。
5. 报告中的「识别语言」是 English；如果实际说中文，请改成「自动」或「中文」，否则识别质量会明显变差。

## 2.2.13：API 稳定性、字幕跟随与助教布局

1. **API 空响应自动重试**：网关偶发返回 200 但 SSE 没有任何 content 时，自动重试最多 3 次（覆盖空响应、HTTP 429/5xx、连接失败），并在界面状态显示“接口空响应，重试 x/3”。这解决“十次只有一次成功”。
2. **API 模式不再并发草稿/校正**：边说边译草稿和上下文校正会各自再发一次 API 请求，容易触发网关空响应或限流；API 模式自动跳过这两项，只保留正式翻译。内置模型模式不受影响。
3. **解析服务端错误**：SSE/JSON 中的 `error.message`、`finish_reason=content_filter` 会直接显示，而不是笼统的“没有返回任何内容”。
4. **字幕自动跟随改为即时滚动**：不再使用动画滚动，语速快或流式 token 频繁更新时也能紧跟最新内容；用户向上翻看时仍不会被拽回底部。
5. **助教面板分为两个等高的独立卡片**：「本场要点」和「问答」各占一半高度、各自滚动，不再挤在同一个列表里。
6. 保留 2.2.12 的麦克风 AppOps/静音/录音状态/路由检查。

## 2.2.14：2bit 模型修复与 API 非流式兜底

1. **2bit 本地模型可以加载了**：腾讯 2bit GGUF 使用尚未合并进上游的 Q2_0C 量化格式（llama.cpp PR #19357）。这一版把 Q2_0C 的块结构、反量化、ARM NEON 点积和文件类型映射移植进了应用自带的 llama.cpp，并把模型源换成腾讯官方 `tencent/Hy-MT2-1.8B-2Bit-GGUF`（约 600MB）。
2. **旧 2bit 文件会被自动删除**：之前从 Arm 仓库下载的 `hy-mt2-1.8b-2bit.gguf` 使用另一种不兼容的编号，无法加载。升级后首次启动会自动删除它；需要到设置 → 模型管理重新下载 2bit 模型。
3. **API 空响应自动改用非流式**：第一次仍用 SSE 流式；如果网关返回 200 但没有任何 content，第二次自动改用 `stream:false` 整包请求。很多“接口没有返回任何内容（SSE）”的网关在非流式下是正常的。
4. **流式请求 20 秒无数据就切换**：不再一直等 180 秒；日志会记录每次请求的 URL、流式/非流式、等待时间和输出字数。
5. **译文长度上限提高**：实时翻译的 `max_tokens` 从 220 提高到 320，减少长句或思考型模型被截断。输出被截断时会明确提示 `finish_reason=length`，而不是笼统的空响应。
6. **已收到的部分译文会保留**：重试或超时前如果已经显示了一部分译文，会保留这部分，不再整句变回“翻译失败”。
7. 保留 2.2.13 的 API 重试、字幕即时跟随和助教双卡片布局。

## 2.2.15：全量代码复查与“不可用状态”修复

这一版按启动、音频、识别、翻译、模型下载、数据库、课程和界面逐块复查，重点修掉会让应用卡在某个状态、丢结果或越用越慢的问题：

1. **启动/结束状态机**：启动过程中现在可以点「取消启动」（按钮和通知都可结束）；修复了“启动过程中点结束”可能留下 running 状态、捕获器或空课次的竞态；结束最多等待 15 秒音频线程，原生 VAD 卡住时也不会永远停在「正在收尾…」。
2. **前台服务被系统杀掉的路径**：`LiveService` 在 starting 状态被销毁时也会停止采集和课次；已有会话时刷新通知失败不会再误杀服务；系统拒绝启动前台服务时主界面直接显示原因，而不是崩溃。
3. **助教不再一直转圈**：问答/总结过程中数据库异常、取消或模型异常都会在 finally 里清掉「思考中」；「最近总结」不会被重复点击堆积。
4. **排队翻译不再用错模型**：每条字幕入队时记录当时的翻译方式/API 地址；排队期间切换到 API 或内置模型，不会把上一场的积压句子发到新接口。切换模型版本时本地线程和版本仍跟随当前设置，避免来回卸载模型。
5. **网关 SSE 为空时自动记住**：某个接口连续返回“200 但 SSE 没有 content”时，10 分钟内后续请求直接走非流式整包请求；模拟网关实测每句从约 1.35 秒降到约 0.52 秒，也减少了日志里的重试噪音。
6. **API 设置运行中锁定**：翻译/助教接口地址、模型、Key、自动检测和测试按钮在同传进行时禁用，避免中途换接口导致个别句子失败或抢占请求。
7. **下载校验更严**：镜像用 200 返回 HTML 错误页时，会校验 GGUF 头并自动换 huggingface.co；旧 2bit 的 `.part` 断点也会随旧模型一起清掉，不再白占几百 MB。
8. **数据库与资料导入**：损坏数据库备份失败时绝不删除原库；资料导入打不开文件会删掉 0 字节临时文件；资料和资料分片写入改为事务并检查插入结果。
9. **课次详情新增「补译 N 句」**：历史课次里因崩溃、模型未就绪或排队超时而空着的译文，可以在课程 → 课次详情里用当前翻译模型一次性补齐；中途开始实时同传会自动停止补译。
10. **界面线程与滚动**：课次详情读取数据库统一回到主线程再更新 Compose 状态；课程问答的流式回调不再从 IO 线程改 UI；全屏字幕等布局完成后再滚到底，避免最新一句偶尔露不出来；API 未填地址时顶部不再误显示“就绪”。
11. **设置容错**：SharedPreferences 里的非法模型、语言、主题、线程数、字幕行数等值会被修正，旧配置不会让应用进入无法启动的状态。

保留 2.2.14 的 Q2_0C 2bit 模型支持、API 非流式兜底、字幕即时跟随和助教双卡片布局。

## 与 macOS 版的差异

- 识别引擎只有 SenseVoice；macOS 版的 Qwen3-ASR / Whisper 未接入（Android 上 1.8B 级识别模型对平板太重）。
- 扫描版 PDF 没有内置 OCR；请先转成文字版 PDF 或直接上传 TXT/DOCX。
- 没有 macOS 全局快捷键；对应操作都在界面里。
- 翻译首字延迟在平板上通常为 **1–4 秒**（取决于芯片、模型和线程数），明显慢于 Apple Silicon 上的 MLX 版本；追求速度可在设置里换 2bit 翻译模型或减少线程争用。
- 浮字幕需要「显示在其他应用上层」权限；系统音频需要每次开始前确认录屏。
