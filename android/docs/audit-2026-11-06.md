## 1. 新字幕取消的不只是草稿（成立，中）

`handleFinal` 里：

```kotlin
if (backgroundTasks.get() > 0 && !finalTranslating) app.llm.cancelTranslation()
```

`backgroundTasks` 在 `handleDraft`(1054)、`maybeCorrect`(1087)、`translateAnswer`(1315) 三处自增。
`cancelTranslation()`（Llm.kt:1092）直接 `translator?.cancel()`，本地生成被打断后返回**部分结果而非抛异常**，于是：

- `translateAnswer`(1327) 把截断片段当完整译文写入 `answerAlt` 并落库；
- `maybeCorrect` 的校正被丢弃（`correct()` 内部有长度/差异校验，多被拦下，属静默跳过）。

**修法**：把「取消草稿」判定换成独立的 `draftInFlight` 标志，只在 `handleDraft` 置位/清零，别用 `backgroundTasks`。

## 2. 助教接口超时不重试（成立，中）

`apiAssistantWithRetry` 的 `retryable` 只匹配空响应、`接口返回错误`、`HTTP 429`、`HTTP 5xx`、连接失败、截断；**没有 timeout / 504 的 SocketTimeout 文案**。读超时 180s，一旦撞上直接抛出。非流式回退只发生在第 2 次尝试，而第 1 次超时进不了第 2 次。

**修法**：`retryable` 增加 `timeout`、`timed out`、`SocketTimeout`、`HTTP 504`。

## 3. 取消钩子迟到（成立，中）

```kotlin
val handle = job?.invokeOnCompletion { cause -> if (cause is CancellationException) n.cancel() }
```

`invokeOnCompletion` 默认在**完成后**回调。生成阻塞在 JNI 里时不返回 → 协程无法完成 → 回调永远等不到 → native 不会被打断。外部 `cancel()`（看门狗那条路）能救，但父作用域取消 / `withTimeout` 取消救不了。

**修法**：`job?.invokeOnCompletion(onCancelling = true) { ... }`。

## 4. 流式 think 过滤器丢尾巴（成立，已复现，中）

`ThinkStreamFilter.feed` 在 `inThink` 状态找不到结束标记时 `buffer.clear()`，把已到的 `</thi` 也清了，下一块 `nk>` 再也匹配不上，`inThink` 永远为 true → 后面所有正文被丢。

我用同样算法跑了三个用例：

```
<think>思考</thi | nk>答案一 | 答案二   -> ""      # 全丢
<think>x</thi | nk | >译文                -> ""      # 全丢
<think>abc</think> | 译文                 -> "译文"  # 正常
```

影响面：只有「流式字幕」这一段不显示；最终结果走 `Think.strip(raw)`（原始串），所以落库/字幕终值仍正确，表现为「字幕卡住、句子最后一下才蹦出来」。

**修法**：`inThink` 分支里若缓冲区尾部 ≤ 12 字符且可能是结束标记前缀，保留而不是清空（对齐 `else` 分支已有的 `<` 前缀保留逻辑）。

## 5. 术语表无字符上限（部分成立，低）

`Database.glossaryPrompt` 有 `take(30)` 条数限制，但 `term`/`translation` 长度无约束，拼进 system 提示没有字符预算。30 条正常术语无碍；异常长条目才可能挤占 2048 上下文。建议加整体长度裁剪（如 600 字）。

## 6. 提问上下文截断顺序不对（成立，中）

`body` 拼装顺序：课堂记录 → 课程背景 → 课件片段，然后 `body.take(4600)` 取**头部**。历史 20 句 + 背景一旦超长，被裁掉的正是不久前算好、最需要的课件片段。

**修法**：先按预算裁历史，再给课件片段留固定配额（或改成「课件片段优先 + 历史按剩余空间回填」）。

## 7. 续传 416 判断用近似大小（成立，边界，低）

```kotlin
if (resp.code == 416 && existing > 0 && existing >= expectedTotal)
```

`expectedTotal` 是枚举里的近似值（如 1_133_000_000）。真实文件比近似值小，tmp 已下满时 `existing < expectedTotal` → 条件不成立 → `HTTP 416` 抛出，两个 host 都失败，下载卡死到用户重试。

**修法**：416 时无条件把 tmp 收编（或先请求一次 `Content-Length`/用 `Content-Range: bytes */total` 的真实总长）。

## 8. 助教关闭时问题永远 pending（成立，低）

`enqueueQuestion` 先插 `pending = true, "思考中…"`；`handleQuestion` 在 `!assistantEnabled && !manual` 时直接 `return`，没人清 pending → 「思考中…」常驻。
同段 1192 行 `sessionId` 不匹配时也是直接 return，同样残留。

**修法**：两处 return 前把该条问题标成 `pending = false` 并给一句说明（或干脆不入队）。

## 9. 无协议地址降级成 http（成立，安全，中）

`normalizeBase`：`if (!startsWith http:// && !startsWith https://) base = "http://$base"`。用户填 `api.xxx.com` 就会走明文，API Key 和译文裸奔。默认应给 `https://`，或直接拒绝不带协议的地址。
