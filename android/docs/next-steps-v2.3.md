# 下一阶段目标：延迟与稳定性（v2.3）

Android 平板版「本地同传」要往「能长期用的成品」推一版。本文件是给编码会话的工作清单，目标可量化、可验收。

## 硬指标（必须测，必须报数）

在**同一段 3 分钟真实课堂音频**、**同一台设备**（arm64 模拟器数据仅作参考，有真机优先用真机）上测：

| 指标 | 含义 | 目标 |
|---|---|---|
| T1 | VAD 断句 → ASR 出结果 | ≤ 400ms（本地 SenseVoice） |
| T2 | ASR 出结果 → 首个译文 token 上屏 | ≤ 500ms（本地 Hy-MT2 1.8B） |
| T3 | 整句最终译文完成 | ≤ 2000ms |
| T4 | 连续讲话时的最大滞后 | ≤ 1 句 |
| T5 | 一场 30 分钟会话的内存增长 | ≤ 100MB，无 OOM |

日志统一打 `AppLog` 的 `Lat` 标签，字段：`segId`, `vadEnd`, `asrDone`, `firstToken`, `finalDone`，并给出 p50 / p95。

## P0 缺陷（先清，来自上一轮 14 项清单）

**A1｜停止录音时可能释放仍在使用中的录音对象（闪退）**
`audio/AudioCapture.kt:161`、`:278` — `join(800)` 超时后仍无条件 `release()`，采集线程在已释放对象上继续读。修法：join 超时就别 release，改由采集线程退出后自行释放，读循环外包异常上报。

**A2｜断点续传可能拼出损坏模型，且失败后无法自愈**
`llm/ModelStore.kt:319`、`:323`、`:331` — 续传前不校验远端是否换版本；416/续传位置不符时 `.part.tmp` 不清除，之后每次重试同样失败。修法：记录 ETag/Last-Modified 并校验；416 用真实总长判断；校验失败删临时文件从头下；向导错误行加「删除并重下」。

**A3｜助教 API 首次流式超时后不重试**
`llm/Llm.kt` 助教重试分支 — 可重试判定漏了 timeout / SocketTimeoutException / UnknownHostException。修法：补进判定，超时后第二次走非流式。

**A4｜推理线程数改小后已加载模型不会被换掉**
`llm/Llm.kt` 本地模型持有处 — 设置改了线程数，预热过的模型仍用旧线程数。修法：设置变更时主动卸载/重建，或下次会话开始时按新值加载。

## 延迟工程（按收益排序）

1. **流水线重叠**：ASR 未完成前不要干等。用流式 partial 结果先起草稿翻译（已有 `handleDraft` 框架），ASR 终稿到达后再走最终翻译，让 T2 与 ASR 尾部重合。
2. **预热**：进入同传前预热 ASR + 翻译模型与 KV 缓冲，把首次 token 的冷启动成本挪到会话开始前（已有 warmUp，确认它真的把权重和 KV 都 touched）。
3. **线程与上下文**：按设备性能核数设置 `n_threads`；`n_ctx` 只给够用的大小，别为了保险开大导致 KV 拷贝变慢。
4. **短句合并**：VAD 切出 < 3 字的碎片时并到下一句，避免一次 80ms 的模型调用换两个字。
5. **草稿限长**：草稿只给 `maxTokens` 小值 + 早停，别让草稿抢最终翻译的算力（二者共用一把锁，注意排队）。

## 稳定性与完整性

- 蓝牙麦克风切换、拔耳机、息屏后前台服务继续跑（`audio/LiveService.kt`）
- 内存压力时自动降级到 2bit / 更小上下文，并在界面说清楚降级了什么
- 会话崩溃后可恢复（已有 loadSession，确认进程被杀后能续上）
- 导出 SRT / TXT，含时间轴与说话人
- 设置项即时生效（线程、模型版本、语言、VAD 灵敏度）

## 约束

- 不重构整体架构，不加新依赖，不改公共 API 签名
- 只动 `android/` 下的源码与构建脚本；不碰 `dist/`、模型文件
- 每批改动后必须 `./gradlew :app:assembleDebug` + `:app:lintDebug`，并在模拟器上做启动冒烟
- 最终交付：改动清单 + 前后 p50/p95 对比表 + 未解决项
