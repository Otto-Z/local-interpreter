# 本地同传 · 功能完善计划书

> 版本：v2.2.3 规划　日期：2026-10-28　当前软件版本：v2.2.3（原生 .app，P0–P6 已实现；课程化、术语表、跨课次问答、课前/课后、存储与评测已完成）

---

## 一、背景

v1.0 已经跑通完整链路：麦克风/系统音频 → Silero VAD 分句 → MLX Whisper 识别 → 本地大模型流式翻译 → 网页字幕界面，并打包成双击即用的 macOS 应用。

下一步要解决的问题：

1. **翻译后端要通用**：只依赖 OpenAI 兼容接口（你实际使用 oMLX，不再围绕 Ollama 做特殊处理）。
2. **分句要更聪明**：加入自动识别能力，减少手动调参。
3. **课堂助教**：右侧栏实时总结本场内容；课堂上有人提问时自动识别并给出参考答案。
4. **传译要留得下**：每次结束自动生成标签（时间、主题等），之后能按标签回看内容。

## 二、现状（v1.0 技术盘点）

| 模块 | 现状 | 局限 |
| --- | --- | --- |
| 音频采集 | v1.0 浏览器采集 16kHz PCM，WebSocket 传输 | 依赖 Chrome；P0 改为原生采集（AVFoundation + ScreenCaptureKit） |
| 分句 | Silero VAD，固定静音阈值（550ms）+ 最长 6 秒强制切分 | 阈值需手动调；不区分语言；嘈杂环境不稳 |

| 翻译 | OpenAI 兼容 `/v1/chat/completions` 流式；Qwen3 走 Ollama 原生接口 | 默认后端绑定 Ollama；特殊分支不通用 |

| 打包 | `build_app.sh` 生成自包含 .app（内置 Python 与依赖） | 无版本升级机制 |

## 三、总体目标与原则

**目标**：核心是**一台 Mac 上完全离线的实时同传**；在此之上，重点做「**课堂助教**」——右侧栏实时总结，课堂上有人提问时自动给出参考答案。归档、标签、检索等能力都围绕这两件事展开，不喧宾夺主。

**原则**：

- **只用 OpenAI 兼容接口**：`GET /v1/models`、`POST /v1/chat/completions`（SSE 流式）。不绑定任何厂商，不为单一后端写私有协议。
- **模型自带**：应用不内置、不预设任何具体模型。你自行在 oMLX 里下载部署，应用只负责发现、测试和调用。
- **完全本地**：录音、识别、翻译、分析、存储全部在本机；不向外部发送数据。
- **渐进增强**：分析、标签、历史都是可选能力；模型不支持时降级而不是报错。
- **延迟优先**：任何新功能不得显著拖慢主链路（识别 + 翻译），分析类任务全部异步、可取消。

## 四、需求方案

### 4.1 翻译后端：纯 OpenAI 兼容（P0）

**要做的**：

1. **删除 Ollama 专属逻辑**
   - 移除启动时自动拉起 `ollama serve` 的行为、移除 Ollama 原生 `/api/chat` + `think:false` 分支。
   - 翻译只走 `/v1/chat/completions`，配置项只有：接口地址、模型名、API Key（可选）。

2. **后端预设与自动发现**
   - 设置页提供预设：**oMLX（`http://127.0.0.1:8000/v1`，默认）**、LM Studio（`1234`）、vLLM（`8000`）、自定义。
   - 点「检测」时依次探测常见端口与 `/v1/models`，列出可用服务、模型清单和首字延迟，一键填入。
   - 保存多套后端配置档（名称 + 地址 + 模型 + key），顶部可快速切换（例如「oMLX·Qwen3-27B」/「oMLX·Gemma-4-26B」）。
   - **不预设任何具体模型**：模型列表全部来自 `/v1/models`，也可以手动填写模型名。首次配置走三步向导：确认地址 → 从列表选模型 → 试译一句并显示耗时。

3. **思考型模型的通用处理**
   - 请求参数按服务能力自动追加（如 `chat_template_kwargs.enable_thinking=false`、`reasoning_effort`），失败则退回基础参数。
   - 流式输出统一过滤 `‹think›…‹/think›` 与 `reasoning_content` 字段。
   - 设置项「关闭思考模式」；若检测到首字延迟过高（>3s），提示可能处于思考模式并给出建议。

4. **连接诊断与容错**
   - 状态栏显示：后端名、模型、首字延迟、最近一次错误。
   - 超时/失败自动重试一次；翻译失败时原文仍然保留并标记。
   - 支持 `/v1/models` 不可用的服务（允许手动填模型名直接使用）。

**验收**：oMLX 在 8000 端口启动任意模型后，无需额外配置即可翻译；断网状态下除首次下载模型外全部功能可用。

### 4.2 分句与自动识别（P1）

> 对「分句功能加入自动识别」的理解：**自动识别语言 + 自动适应现场的分句参数**。如你的本意不同，实施前再确认。

**4.2.1 语言自动识别**

- 每段识别时检测语言，但加入**滞回**：只有连续 2 段的检测结果与当前语言不同，才切换；避免中文里夹一句英文就来回跳。
- 界面每行显示语言徽标（中/EN/…）；`翻译成 = 自动` 时按「中文↔英文、其它语言→中文」取反。
- 会议场景支持**双语交替**（一人中文、一人英文）：语言随之切换而不会强制同一种。
- 增加「锁定识别语言」开关（默认关）：锁定后所有片段使用同一语言，速度更快、专有名词更稳。
- 性能：自动检测当前每段多约 0.5s。方案是**仅在语言可能变化时重新检测**（检测结果带概率，低于阈值才重检），稳定场景下回到 0.6s/段。

**4.2.2 自适应分句**

- **环境校准**：开始后前 3 秒统计噪声底，自动设定 VAD 阈值；支持「安静房间 / 普通 / 嘈杂（会议室、外放）」三档。
- **动态静音阈值**：默认 550ms，按语速自动在 350–900ms 之间调整；说话快的人更早断句，慢的人给更长的停顿余量。
- **自然切分**：强制切分时在低语音概率处下刀（已实现基础版），进一步加入「标点/连词」倾向（在「但是、然后、所以」等之前切）。
- **防误触**：咳嗽、键盘声、音乐不进入识别（VAD 置信度 + 最短语音时长 + 能量过滤）。
- **低延迟模式（可选）**：partial 预览也走翻译，先显示草稿译文，句子结束后用最终译文替换（带淡入更新），主观延迟可降到 1 秒内。

**验收**：在安静房间与有背景音的会议室各录 5 分钟，切句位置 90% 落在语义边界；中英混说能自动切换；无需手动调参即可使用。

### 4.3 会话归档与自动标签（P3）

**4.3.1 会话模型**

- 「开始」到「停止」为一场会话；异常退出（崩溃/关窗口）也保存，标记为「未正常结束」。
- 每场会话记录：开始/结束时间、时长、音频来源、识别语言分布、翻译语言、全部原文与译文（带时间戳）、使用的后端与模型。

**4.3.2 结束自动生成标签**

会话停止后 3–10 秒内，由同一 OpenAI 兼容模型生成一次结构化结果（单次调用，JSON 输出，失败则走规则降级）：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `title` | 一句话标题 | 「周三项目评审会：原型与排期」 |
| `topics` | 3–6 个主题标签 | 项目评审、原型、发布计划 |
| `summary` | 80–150 字摘要 | … |
| `kind` | 场景类型 | 会议 / 访谈 / 课堂 / 视频 / 闲聊 |
| `questions` | 对话中出现的问题 | 「上线时间能否提前到 11 月？」 |
| `actions` | 待办/决定 | 「张三本周五前发新原型」 |

规则降级方案：标题取前两句关键词；标签取高频词（TF-IDF）；问题用疑问词与问号规则抽取。

**4.3.3 历史库界面**

- 新增「历史」页签：按时间倒序的卡片列表，展示标题、时间、时长、标签、语言、摘要首行。
- 搜索：SQLite FTS5 全文检索原文与译文；按标签、日期、语言、场景类型筛选。
- 详情页：双语对照（原文/译文并排或上下）、时间轴定位、音频播放（点字幕跳转、倍速、按句前进/后退）、标签可手动增删、重新生成标签、导出 Markdown / SRT / JSON。
- 会话可删除、可置顶、可加星标；设置里配置保留策略（如保留 90 天或最多 200 场）。
- 音频（已确认默认开启）：每段音频随字幕一起保存，点击字幕即可回听定位。采用 AAC/Opus 压缩存储（约 15–30MB/小时）；编码器不可用时退回 WAV，并在设置里提示空间占用。删除会话时一并删除音频。

**存储**：SQLite 单文件，位于 `~/Library/Application Support/本地同传/history.db`；启动时自动迁移，损坏时自动备份重建。

**验收**：任意一场会话结束后 10 秒内出现带标题/标签/摘要的记录；搜索「原型」能在 1 秒内定位到相关场次与句子。

### 4.4 侧边栏：实时总结与课堂问答（P2，核心场景）

定位：软件首先是「离线同传」，其次是一个**课堂助教**。典型使用方式是上课/听讲座：一边看字幕，右侧栏持续显示本场内容总结；课堂上有人提问（老师或同学）时，自动识别问题并给出参考答案。

**4.4.1 布局**

主界面两栏：左侧字幕（保持现状），右侧「助教」栏（宽 340–380px，可收起、可拖拽调整）。栏内两个区块：

1. **本场要点**：实时滚动的总结，3–5 条短句，带最后更新时间。
2. **问题**：按时间倒序的问答卡片。课堂上一出现提问，就新增一张卡片（问题原文 + 译文 + 答案），不区分提问的是老师还是同学。

字幕模式下右侧栏自动隐藏；期间检测到新问题时，在字幕底部用一个小角标提示「有 1 个新问题」。

**4.4.2 实时总结**

- 触发：每 60–90 秒或每 12–15 句触发一次；采用**增量式总结**（上一版总结 + 新增句子 → 新一版），避免全量重算、也避免总结内容逐渐漂移。
- 输出：3–5 条要点、当前主题、出现的关键术语/概念。
- 展示：更新时只改动有变化的部分，避免整块闪烁；点击某条要点可跳转到字幕中的对应句子。
- 失败静默：模型忙或报错时保留上一版，不弹错误、不打断听课。
- 与归档的关系：会话结束时用同一次模型调用生成完整摘要和标签（P3），供课后回看。

**4.4.3 提问 → 及时答案（任何人的提问）**

- **范围**：课堂上任何人（老师或同学）提出的问题都处理；不预设提问者身份。说话人区分（P6）上线后，卡片会标注「老师提问 / 同学提问」，但不影响是否作答。
- **判定**：优先用译后文本判断（中文疑问特征更明确），先用规则（问号、疑问词、疑问句式），再让模型二次确认「这是课堂中一个需要回答的问题吗」，过滤反问、设问、自问自答和同学间的寒暄。
- **节奏**：问题卡片在问题说完后立即出现（显示「思考中…」），答案流式填入；问题说完后 2–4 秒内出答案。同一问题 30 秒内只答一次。
- **答案来源（已确认）**：**课堂内容优先**；课堂内容不足以回答时，再用**模型知识补充**。每张答案卡片标注来源（「依据课堂内容」/「补充模型知识」）；两者冲突时以课堂内容为准。
  1. **课堂内容**：基于本场最近 20 句 + 当前滚动总结回答，例如「老师刚才讲的三个条件是……」。
  2. **模型知识**：概念题、计算题、常识题在课堂内容不足时，用本地大模型自身知识作答。
  3. **课件/教材**（P5，见 4.7）：上传 PDF/讲义后做检索增强，答案引用来源页码。
- **语言（已确认：双语）**：答案同时给出**中文**与**译文语言**两个版本。主语言用正文字号，另一语言用小一号的辅助字号；设置里可以互换主次（例如课堂上需要直接用英文回答老师时，把英文设为主语言）。问题本身也同时显示原文与译文；若译文语言就是中文，只显示一次，不重复。
- **生成顺序**：先流式生成主语言答案（用户第一时间能看到），辅助语言随后生成或翻译补上，不给首屏增加等待。
- **免责提示**：每张答案卡片标注「AI 生成，仅供参考」。
- **已知限制**：数学公式、代码、图表的口头描述识别质量有限，这类问题的答案可能在卡片上标注「涉及公式/图表，可能不准确」。

**4.4.4 资源与优先级**

- 请求优先级：**翻译 > 问题答案 > 滚动总结**。
- 单一请求队列：新的翻译请求到来时，进行中的总结请求可被丢弃（下一轮重来），答案请求保留但让出算力。
- 模型建议：翻译与分析共用同一个 9B 级模型最划算；若翻译换成 27B 级，分析排队会明显，需要在设置里单独指定一个更小的分析模型。
- 总结、问答分别有独立开关，默认开启；不使用时右侧栏不产生任何模型调用。

**验收**：20 分钟中英混合课堂中，总结每 90 秒更新且无明显遗漏；课堂提问（老师与同学）召回 ≥80%，答案在 4 秒内出现，误报 ≤2 条；翻译首字延迟 P95 增幅 <200ms。

- WebSocket 自动重连；服务进程异常退出时由 App 启动器重启一次。
- 日志分级，设置页可查看最近 200 行并「打开日志目录」。

### 4.7 课件知识库（P5，已确认要做）

让答案能引用上传的讲义/PDF，而不是只靠课堂内容和模型自身知识。

- **上传**：PDF、Word、PPT、Markdown、TXT；拖到侧栏「课程资料」或从设置添加。文件保存在本机会话目录，不上传。
- **解析**：本地提取文字（PDF 用 PyMuPDF/pdfplumber；Office 文档转为文本），按标题/段落切块（约 500–800 字，记录页码与章节）。
- **索引**：优先用本地向量检索（oMLX 若提供 `/v1/embeddings` 就直接用；否则用随应用打包的轻量嵌入模型）；两者都不可用时退回 SQLite FTS5 关键词检索（BM25），保证完全离线可用。
- **答题**：检索最相关的 8 个片段，与课堂上下文一起送入模型；答案卡片标注「依据课件：第 12 页 / 第 3 章」。
- **来源优先级（建议）**：课堂内容 > 课件 > 模型知识；每条答案都标注实际使用了哪一层。
- **扫描件**：图片型 PDF 已接入随应用附带的 macOS Vision OCR（中英文，完全离线）。
- **验收**：上传 30 页讲义后，针对讲义内容的提问能引用正确页码；未启用课件时不产生额外常驻负载。

### 4.8 说话人区分（P6，已确认要做）

- **目标**：字幕和助教卡片能标出「老师 / 同学 A / 同学 B」；总结可按人拆分（老师讲了什么、同学问了什么）；问题卡片标注提问者。
- **方案**：本地声纹嵌入模型（优先 ONNX/MLX 的轻量方案，如 WeSpeaker/pyannote 的 ONNX 版本）对每段音频提取向量，在线聚类得到说话人；同一人的句子跨段合并。
- **命名**：首次出现显示「说话人 1」；一键重命名为「老师」「同学 A」，命名随会话保存，同一音色后续自动沿用。
- **展示**：字幕行左侧色点 + 名字；问题卡片标「老师提问 / 同学提问」；总结区分「老师讲了…」「同学问了…」。
- **性能**：每段额外约 20–50ms（CPU），模型约 10–30MB，不影响实时链路。
- **限制**：多人同时说话、音质差、音色接近时准确率下降；允许手动纠正某一段的说话人。
- **验收**：两人交替说话的课堂中，说话人切换识别准确率 ≥85%；手动改名后同一音色自动沿用。

### 4.9 原生 macOS 外壳（P0，已确认）

- **目标**：双击即用的 macOS 应用，不打开任何浏览器窗口；一个窗口、一个 Dock 图标、原生菜单。
- **结构**：Swift 原生外壳 + 内置 Python 引擎 + 内置 WKWebView 界面。外壳负责窗口、菜单、音频采集和引擎进程的生命周期。
- **音频采集**：麦克风用 AVFoundation（AVAudioEngine），系统声音用 ScreenCaptureKit；统一转换为 16kHz 单声道 Float32，经 WebSocket 送入本地引擎。不再依赖 Chrome 的「共享屏幕」。
- **权限**：首次使用时请求麦克风与屏幕录制权限；被拒绝时提示去「系统设置 → 隐私与安全性」开启，并说明原因。
- **生命周期**：启动时拉起内置引擎并等待就绪；退出时结束引擎进程；重复启动时复用已运行的引擎。
- **界面**：沿用现有界面，嵌入应用窗口（无地址栏、无浏览器 UI）；P2 再做侧栏布局调整。
- **移除**：Chrome 依赖、启动 Ollama、浏览器端路径仅作为开发调试备用。

## 五、数据模型（SQLite）

```sql
CREATE TABLE sessions (
  id            INTEGER PRIMARY KEY,
  started_at    TEXT NOT NULL,            -- ISO8601
  ended_at      TEXT,
  duration_s    REAL,
  audio_source  TEXT,                     -- mic | system
  source_langs  TEXT,                     -- JSON: {"zh":0.8,"en":0.2}
  target_lang   TEXT,
  backend       TEXT,                     -- 后端名 + 模型
  title         TEXT,
  topics        TEXT,                     -- JSON 数组
  summary       TEXT,
  kind          TEXT,
  starred       INTEGER DEFAULT 0,
  status        TEXT,                     -- finished | interrupted | running
  tag_state     TEXT                      -- pending | ready | failed
);

CREATE TABLE segments (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  speaker_id INTEGER REFERENCES speakers(id) ON DELETE SET NULL,
  t0         REAL, t1 REAL,               -- 相对会话开始的秒数
  src_lang   TEXT, src_text TEXT,
  tgt_lang   TEXT, tgt_text TEXT,
  audio_path TEXT                         -- 默认保存（压缩音频），可为空
);
CREATE INDEX idx_segments_session ON segments(session_id, t0);

CREATE TABLE speakers (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  label      TEXT,                        -- 说话人 1 / 老师 / 同学 A
  color      TEXT,
  embedding  BLOB                         -- 声纹向量，用于跨段聚类
);

CREATE TABLE questions (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  segment_id INTEGER,
  question   TEXT, answer TEXT,
  created_at TEXT
);

CREATE TABLE analyses (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  kind       TEXT,                        -- summary | points | qa
  content    TEXT,
  created_at TEXT
);

CREATE VIRTUAL TABLE segments_fts USING fts5(
  src_text, tgt_text, content='segments', content_rowid='id'
);
```

## 十、决策与待确认问题

**已确认**

1. **答案依据**：课堂提问以课堂内容为准；课堂内容不足以回答时，再用模型知识补充；答案卡片标注来源，两者冲突时以课堂内容为准。
2. **回答范围**：课堂上任何人的提问都识别并生成答案，不限于老师/讲者。
3. **答案语言**：双语显示——中文 + 译文语言；主语言正常字号，另一种小一号；设置里可互换主次。
4. **分析模型**：允许单独指定更小的模型，不强制与翻译共用。
5. **课件依据**：支持上传讲义/PDF，作为答题依据（P5，见 4.7）。
6. **模型部署**：模型由你自行在 oMLX 中下载部署，应用不内置、不预设具体模型；只提供 oMLX 地址预设、模型发现和连接测试，模型名由你填写或从列表选择。
7. **音频保存**：每段音频默认保存，随字幕回听定位；压缩存储约 15–30MB/小时，删除会话时一并删除。
8. **说话人区分**：需要，排进 P6；字幕与助教卡片标注老师/同学，支持手动命名与纠正。
9. **原生应用**：只交付 macOS 应用，不打开浏览器；音频由原生层采集（P0，见 4.9）。
